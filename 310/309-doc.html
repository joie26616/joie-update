1.2 需求说明

  • V1 一律不变:每日/每周任务列表 4 个新增入口(充提/投注/邀请/充值投注,GetDailyConfig/GetWeeklyConfig?projectID=1/2/3/5)及各配置页 V1 字段(任务类型/任务名称/任务分类[级联]/目标类型/任务目标/任务排序/开启状态),不合并表单、不改任务分类选项。
  • #1 展示条件(新增):[全员] / [充值要求];选中「充值要求」→ 显示 [首充/人] + 金额输入框,首充达标会员才可见此任务。
  • #4 领取方式(加选项):V1 两项文字改为「即时直接领取 / 即时开宝箱领取」,新增 [任务结束];选中 → 领取形式 ① 直接领取 ② 宝箱领取 + 领取有效时间(天,默认 0=不限期,以任务结束时间为准)。
  • #38 邀请任务:任务分类=邀请人 → 新增 领取条件 [充值/人+金额](被邀请人每人充值达标才可领);目标类型=邀请人数 → 必填 [首充额度/每人];归属 tab_DailyConfig/WeeklyConfig「邀请任务」类型,非独立「邀请人任务」(tab_Tasks)。
  • #37 前端 · 活动奖励/任务中心:加筛选(任务周期 周/日 + 任务类型);筛选 pill 红点=该类有「完成可领取」;邀请卡 invited/Deposit 比值(ⓘ);双态优化(上期可领未领置顶高亮 + 本期进度分区 + 顶部聚合一键领取)。

② 任务领取记录(日/周合并) — task-record-309.html ↗
功能面包屑=活动奖励;搜索照抄 V1(会员ID/任务名称/任务周期[默认日任务]/选择类型/领取机制/领取状态/完成时间/领取时间);汇总(发放记录/发放额/已领额/待领/已过期/领取率)按查询条件统计;列:用户ID/订单号/周期/任务名称/任务类型/奖励金额/完成时间/领取时间/🆕领取机制/🆕领取状态/🆕奖励领取率/🆕领取有效期,无操作列。
规则🆕[奖励领取率]:记录级表上的用户维度聚合指标 —— 当前查询范围内该用户ID「已领取到账个数/发放个数」,格式 个数/个数(如 3/4);同一用户多行同值(可含未显示在本页的其他发放记录);分子=ClaimStatus=已领(含即时旧记录、宝箱开箱),分母=发放记录数(by CreateDate)。
交互快捷键 [今天][本周] 在重置后左对齐;横滑 + 前两列(用户ID/订单号)冻结。
技术D-22 口径:CreateDate=发放、FinishDate=任务完成(V1 语义不变),[领取时间]=🆕ClaimDate;历史零回填,读取端 RewardMode 空/0 ⇒ 领取时间=CreateDate;资金只在写 ClaimDate 时记账、过期不冲账。
③ 数据统计 · 每日/每周奖励详情 — award-stat-detail-309.html ↗
功能方案①(D-23):V1 指标卡样式,「每日/每周奖励:金额,N次,N人,🔗详情」原指标零改动=实际领取到账口径(账变来源);行内 🆕 子指标 发放额/笔数(by CreateDate)· 待领 · 已过期 · 领取率(=到账÷发放);搜索条件零新增(日期/渠道/代理ID 照 V1);🔗详情 → 资金账变记录,🆕待领/过期明细 → 任务领取记录。
技术领取额 by COALESCE(ClaimDate, RewardMode=0→CreateDate) + 已领;对账 发放额−到账额=待领+过期,靠 OrderNo 打通;所有资金/成本报表统一到账口径,不走发放。

3.2 宝箱规则优化

treasure-chest.html ↗(单独页面/前端说明)
功能开宝箱领取 = V1 ReceiveType=2;展示区间(前台「最高可得」文案)vs 实际区间(实开随机);任务结束类宝箱带领取有效期。
交互全屏宝箱弹窗、多任务连弹;进入 bonus collection 若有待开宝箱优先自动弹(任务结束类在有效期内每天登录仅自动弹一次),也可随时从列表卡 Receive 手动开;开箱动画 → 揭晓实发金额 → 收下 → 列表宝箱卡不再显示;宝箱不进一键领取、不计入合计,必须逐个开箱;过期未开 → 卡片消失、奖励回收。
技术实发由后端按实际区间随机并落 ActualAmount(报表/账变按实发,严禁把展示区间当到账);开箱=领取,写 ClaimDate + 账变;每日仅自动弹一次需服务端/本地记「当日已弹」标记;开箱接口幂等防连点。
