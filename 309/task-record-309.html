🟣 更新点(#4 领取有效期 + 发放/领取拆分 + 日/周合并)

V1 原字段不动:CreateDate(发放) + FinishDate(任务完成)。🆕 新增:ClaimDate(领取到账时间·可空,本表 [领取时间] 列即此字段;RewardMode=0 时读取端视同 CreateDate)、领取机制(即时/延迟·发放时快照)、领取状态(待领/已领/已过期·当 ClaimDate 为空时区分待领vs过期)、领取有效期(邀请任务=任务结束+N天)、实发值(开宝箱)。日/周两表合并本页,「任务周期」筛选切换。
🆕 [奖励领取率] 列规则:本表一行=一次发放(记录级),而奖励领取率为用户维度聚合指标 —— 按当前查询范围内该用户ID的「已领取到账个数 / 发放个数」计算,显示格式为个数/个数(如 3/4);同一用户的多行显示相同值(数值可含该用户未显示在本页的其他发放记录)。分子=ClaimStatus=已领(含即时旧记录、宝箱开箱到账);分母=发放记录数(by CreateDate)。

⚠️ 防历史污染(硬规则)

1. 资金/成本口径走"到账":统计已领额用 ClaimDate + 领取状态=已领,不用发放 → 待领/过期不计成本、不虚增。
2. 发放口径走 CreateDate;两口径分列,旧数据(即时)读取端「领取时间视同 CreateDate」自动等价,可回溯一致。
3. 不重定义任何 V1 字段(D-22)——CreateDate/FinishDate 语义与现有 SP/SQL/报表/V1 页面用法一律不动;领取只写 🆕ClaimDate,靠领取状态兜底。
4. 延迟模式发放不入账/不计打码量,领取(写 ClaimDate)时才入账;过期 ClaimDate 恒空、只置状态、不冲账。

✅ 迁移(最小改动)

增量字段(含 ClaimDate)全部可空/默认;存量零回填——历史数据不做任何 UPDATE,读取端统一兜底(RewardMode 空/0 ⇒ 即时/已领/领取时间=CreateDate);有效期从 ConfigDetailId→配置次日快照取、发放时写死防漂移。 * 全部为原型占位数据。
