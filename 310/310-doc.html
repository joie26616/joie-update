一 · 月签到 · 需求与规则总览

1.1 对应需求

#19 月签到升级(月签+补签+满签)🆕 奖励判定方式(连续/累计)🆕 领奖有效期
⏸ #36 七日集星产品内部暂停,不列入 310 优化范围,不在本目录。

1.2 需求说明

  • 签到 7 天单套 → 月签 · 分 VIP 路线:每天「充值金额 + 可领取奖金」,31 天全可配;自然月按实际天数(28/29/30/31)自动截断。
  • 签到奖励节点(Milestone):节点(如 3/7/15 天)运营可自由增删调 + 满签大奖恒落当月最后一天;🆕奖励判定方式 开关 —— 连续签到(断签未补则重算,补签可续)/ 累计签到(当月累计达标,允许间断),仅影响节点/大奖判定,不影响每日奖与补签。
  • 补签:只能往前补 N 天(默认 5)· 分段倍数 · 补发比例(默认 50%)· 无次数上限;需充值 = 被补那天的充值金额 × 段倍率(自动计算);确认补签跳存款页;漏签超补签窗口 → 连续中断。
  • VIP 路线锁档:当月首次签到时自选 ≤ 当前等级路线并锁定当月(中途升级不影响,下月重选);后台无需配置。
  • 领取两类:每日签到奖 = 签到页弹框领(沿用现状);节点/满签大奖 = 达成即发放,按 🆕领奖有效期(当月末 23:59 / 达成后 N 天 / 不限)领取,纳入 309 统一领取 / 一键领取(bonus collection 待领取)。

二 · 前台 · 月签到页

① 月签到(前台) — monthly-signin.html ↗
功能31 天日历(按当月实际天数渲染);VIP 路线选择(≤ 当前等级);每日签到(充值门槛 + 奖励);补签(分段倍数 · 补发半额);签到奖励节点与月末大奖展示;当日签到合并领取。
交互当月首签弹路线选择并当月锁定;补签三场景弹框(a 单日 / b 多日累计 / c 触发阶梯 —— 无边框表单、× 关闭,确认补签 → 存款页);月中进入按已锁路线展示;节点达成状态与领取倒计时。
技术配置一律经 GetSignInConfig(SelectedVip, 当月) 实时取;锁档表 MemberSignInMonth(MemberID+YearMonth 唯一,选择时校验 ≤ 当前等级);判定方式(连续/累计)决定节点进度算法与文案;发放时快照金额 / ClaimDeadline。

三 · 后台配置(单模版制)

① 签到配置 — monthly-signin-admin-v2.html ↗
功能每 VIP 仅 1 套 31 天配置、全月通用(录入量 12→1;修复原 3 模版制无平年 2 月 28 天的缺口)。四区:① 快速配置(基础值一键填充 / 区间批量修改,仅辅助不落库)② 每日签到 31 行(例外日高亮 / 29-31 行短月标注 / 节点只读投影)③ 签到奖励节点(判定方式开关 + 领奖有效期 + 节点自由增删 + 批量生成节点[间隔+首值+递增+最高上限=满签大奖] + 满签大奖固定行)④ 补签规则(补签天数 / 分段 / 倍率 / 补发比例 / 需充值自动 / 覆盖度条)。顶部:跨 VIP 递增生成(倍率 × / 固定增量 +,充值与奖励分别配置)。
交互软提示不阻断(空值 / 充值 0 补签免费 / 节点 >28 短月不可达 / 分段缺口重叠 / VIP 倒挂);节点重复输入自动定位既有行;[保存并配置下一 VIP];生成弹窗黄底建议值(改过变白)、覆盖前列出目标确认;未保存离开拦截。
技术数据模型 = SignInTpl / SignInDay / SignInMilestone(RewardType: Normal/Completion) / SignInResignSeg + 会员侧 MemberSignInMonth;基础值与工具参数不落库;补签需充值 = 当天充值 × 倍率;MilestoneMode(1连续/2累计)、ClaimWindowType/Days(领奖有效期,发放时快照)落主表;详见《310-月签到-单模版配置数据模型(定稿).md》。

六 · 数据模型与扩展预留

  • 配置模型(定稿):SignInTpl(聚合根:补签天数 / 判定方式 / 领奖有效期)+ SignInDay(31 行)+ SignInMilestone(Normal 节点 + Completion 满签大奖)+ SignInResignSeg(补签分段)+ 会员侧 MemberSignInMonth(月锁档);基础值与批量工具参数一律不落库。
  • 唯一读取入口 GetSignInConfig(vip, yyyymm):截断 / 大奖重锚 / 判定口径 / 领奖窗口全在入口内解析;禁止散点直查配置表。
  • 运行期:实时读取 + 发放时快照(金额 / ClaimDeadline 写死进会员记录),改配置即时作用于未发放部分、历史不受污染。
  • 扩展预留(不构成当前版本开发范围):A 月度配置覆盖(稀疏覆盖层,入口内 merge)/ B 月份级开放控制(SignInOpenMonth 轻量表 + 入口一次校验);硬性约束:不新增复杂配置体系、不做月份维度核心重构,扩展只允许「入口层扩展 + 新增轻量表」;若排期先 B 后 A。
