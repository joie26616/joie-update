📌 需求点说明 / 业务·技术风险 / PRD(配置·数据交互)
一、本页相对现状的调整点(后台)
  • 签到固定为 月签 · 按自然月;补签天数(原"补签上限N次"→改为可往前补的天数,默认5)移至 VIP 配置基础值区。
  • 新增 分 VIP 等级配置(VIP1–10·原全站一套):每 VIP 一套路线,基础值批量填充 + 31 天逐日微调。
  • 满签阶梯奖融合进「每日签到明细」表(里程碑日 3/7/15/满月 直接配奖金);补签分段(区间→倍数+补发比例)单独配置表。
二、业务风险与建议
  • 配置项多(VIP×31天)→ 运营录入易错。建议:基础值批量填充 + 复制路线 + 保存前校验「等级越高条件不低于低等级」(软提示)。
  • 补签天数/倍数设置过松易被刷,过紧体验差。建议:默认 5 天 + 分段倍数递增 + 补发半额,给推荐值。
  • 大奖按当月最后一天:小月(2月)门槛更低。建议:运营知悉,必要时按月微调大奖额。
三、技术风险与建议
  • 自然月天数动态 → 大奖节点/补签区间按当月天数实时计算,后端 SP 与前端统一口径。
  • 不破坏 V1 tab_SignInRecharges 现状 → 新增多表承载 VIP×31天/满签/补签;旧 7 天逻辑保留可回退。
  • 补签计入连续 → 满签判定实时重算;补签/领取接口幂等 + 去重防并发重复发奖。
四、PRD · 配置与数据交互
  • 配置(5 表):活动主表(模式/周期/补签天数·无上限/首日选线)、VIP 路线表、按天明细表、满签阶梯表、补签分段表。
  • 运行(2 表):会员月签到主记录(路线/首签日/当下连续/各阶梯领取状态)、每天状态明细(已签/漏签可补/超期/补签·打钩·扣款)。
  • 保存配置:写 VIP×31天矩阵 + 满签 + 补签分段;前台 GetMonthlySignIn / DoSignIn / DoRetroSignIn / ClaimMilestone;满签奖走 309 统一领取。详见 docs/superpowers/specs/2026-06-29-monthly-signin-310-design.md。
