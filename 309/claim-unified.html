★ #21 活动奖金领取提醒弹窗(整合进 Bonus collection)

触发场景:有充值过的会员,玩彩票最后一注输了 / 三方游戏退出返回平台,当 当前余额 < 最低下注金额 时,自动弹出 Bonus collection(即本面板),把平台目前已开启的全部活动聚合到一个面板,看进度 + 一键领取。

目的:会员激情游玩输完想及时跟注时,有几个活动刚好达标 → 快速领取继续玩,不用一个个找活动页;充值走游戏页顶部「＋ 充值」。

游戏页浮窗(图3):游戏页右下 🎁 浮窗小按钮(带可领数字角标)。点击分流:仅剩宝箱可领 → 当前游戏页直接弹宝箱开箱(不进面板);除宝箱外还有其他待领 → 进 Bonus collection(沿用现有面板逻辑)。

与 309 复用:本面板 = Bonus collection,完全复用统一领取 / 一键领取 / 状态机(下方 1~6 规则);#21 只新增「触发时机 + 游戏页浮窗入口 + 充值引导」,不重复造领取逻辑。

样式

以 V2 真实 Bonus collection 弹窗为准(白卡:🪙图标 + 着重金额 + 奖励名 + 红色 Receive),做最小优化。

1. 一键领取 + 总额(顶部固定)

顶部「共 N 项待领取 · 合计 ₹XXX」(金额着重红大字)+ 一键领取按钮,顶部固定不随列表滚动。

2. 统一领取反馈

单项/一键成功 → 统一弹窗(✓ + 单项金额 / 多项列表+合计);一键支持 全部成功 / 部分成功(✗原因)/ 全部失败,失败原因沿用 V1 msgCode。

🆕 部分成功·失败原因口径(本次新增):一键领取只会提交「已可领」的项(待领 且 已到领取开始时间;Check 跳转类、宝箱类不提交),因此结果弹窗中不会出现「未到领取时间 / 不满足条件」两类失败;真实可能出现的失败仅为领取瞬间的竞态两种(沿用 V1 msgCode):① 已过期 —— 点击一刻恰好超过领取截止时间;② 已领取 —— 已在其他入口/设备领过,防重命中。前端逐项展示失败原因,不阻断其他成功项到账。

3. 结合活动结束领取(#4)

活动结束领取的奖励显示有效期倒计时;月任务多笔逐笔列出;未到领取时间置灰;已过期不显示。

4. Check(跳转参加)类保留现状

Receive=直接领取(走统一弹窗+计入一键);Check(↑最高可得)=跳转参加类,保留 V2 现状(跳活动页,不弹领取、不计入一键)。

5. 已领取不显示

已领取的奖励项不再显示(同已过期);列表只保留 待领取/未到领取/可参与。

6. #20 充值赠送彩金纳入

原 #20「弹窗领取」充值赠送彩金已纳入列表(带过期倒计时),领取交互与统一规范一致;会员登录后若有该笔未领,直接弹本 Bonus collection。

7. 宝箱规则(开宝箱领取)

任务编辑(#4)「领取形式」=直接/开宝箱;开宝箱=V1 ReceiveType=2,展示区间(诱饵)vs 真实区间(实开);点开宝箱→动画→揭晓实开额→统一成功弹窗;任务结束类宝箱未到期置灰、倒计时。详见 treasure-chest 页。

🆕 宝箱入口与连弹(本次调整):宝箱不进一键领取、不计入合计,需逐个开箱看动画。 入口移到标题「Bonus collection」后(图2):有宝箱可开时 🎁 晃动提示 + 数字角标,点击开箱;无宝箱时置灰表示「无宝箱可领取」。 进入面板若存在待开宝箱仍优先自动弹(每天首次登录一次);多个宝箱连弹(开完一个自动弹下一个),开箱到账后该宝箱卡消失、标题角标递减,全部开完 🎁 转灰。 弹框可关闭(图1):点右上 ✕ 稍后再开,宝箱卡保留、标题 🎁 继续晃动提示。宝箱列表卡的 Receive 也可单独开对应宝箱。纯前端展示/交互调整,不涉及后端逻辑与接口。

9. 底部充值栏(本次移除)

原「#21 底部固定充值引导条」已移除;充值统一走游戏页顶部「＋ 充值」按钮(游戏页浮窗分流见「目的/游戏页浮窗(图3)」)。

🛠️ 接口 / 字段说明(前后端评审用 · 点击展开)

一、后端接口更新需求

1. 列表接口扩展(GetRewardCenterList):每项新增 orderNo(幂等键+对账)/claimStatus(1待领/2已领/3已过期)/claimStartTime(可领开始=任务结束时间)/claimDeadline(领取截止·发放时快照)/receiveType(1直接/2宝箱)/rewardMode(0即时/1延迟);已领/已过期项服务端不返回(本页不显示)。
2. serverTime:列表响应带服务器时间,倒计时以此为基准(本页演示暂用客户端时间)。
3. 单项领取:入参 orderNo;成功即写 🆕ClaimDate + 资金账变 + 打码量(D-22:写 ClaimDate 那一刻才动钱);宝箱返回 actualAmount(实发·后端按实际区间随机);失败返回 V1 msgCode(已领取/不满足/已过期/未到领取时间/请勿重复提交)。
4. 🆕一键领取:批量 orderNo[](仅待领且已到 claimStartTime;Check 跳转类不纳入);逐项独立结算,返回每项成功(含 actualAmount)/失败(msgCode)→ 前端三态结果弹窗;整批幂等。
5. #38 邀请任务:返回「被邀请人充值 ≥N/人」达成进度,未达标 ReceiveStatus=0+原因。
6. 红点(#40):Activity 红点 = 待领项数(claimStatus=1 且已到 claimStartTime)聚合。

二、前端交互

待领在前 → 未到领取时间置灰在后;已领/已过期不出现;每卡显示 claimDeadline 实时倒计时。receiveType=1 直接领取→统一成功弹窗;=2 拉起全屏宝箱弹窗开箱,到账以 actualAmount 为准(任务结束类宝箱:有效期内每天登录仅自动弹一次)。一键领取→三态结果弹窗(全成/部分成功逐项 msgCode/全败),[知道了] 后刷新列表与红点。金额红线:宝箱项只展示「最高可得」(展示区间上限),不得当到账金额;RecordType=1 比例 ×100 显示。

三、字段定义(D-22 口径 · 前后端都要盯)

CreateDate/CreateTime=记录创建/发放(V1 语义不变,列表 CreateTime 是发放非到账);FinishDate=任务完成(V1 语义不变,绝不当领取时间用);🆕ClaimDate=领取到账(可空·唯一承载领取;只有写入这一刻才记账变/打码量;过期恒空不冲账;历史零回填,读取端 RewardMode 空/0 ⇒ 领取时间=CreateDate);OrderNo=发放唯一键(领取幂等+账变对账);ClaimDeadline/claimStartTime=领取窗口(发放时从次日快照写死,不引用配置现值;#38 首充门槛是发放前判定,与领取窗口别混);ActualAmount=宝箱实发(报表/账变按它);ReceiveStatus 维持 V1 两态(0/1)不扩枚举,新中间态由 claimStatus+时间窗承载。
