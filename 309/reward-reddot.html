实现状态核对(基于 V1 后台 + V2 前端代码):本需求全部为「新增」,现状均未实现。
· V2 底部导航 TabBar = home / activity / promotion / wallet / main,无任何红点/角标;中间第 3 个是 promotion(邀请转盘 Get ₹100),无 Deposit;
· 全前端无「可领/可参与 红点」机制;V1 后端无红点聚合/未领数接口(仅有 GetRewardCenterList 的 ReceiveStatus/MaxRewardableAmount 字段可作数据基础)。
沿用现状(不改):底部 5 个 tab 框架、promotion 中间高亮位、wallet 钱包入口。下列为新增优化 ↓
红点 = 有奖励待领取 或 满足参与条件
  • 底部导航 Activity:其下任一活动「有奖励待领取」或「满足参与条件」→ 显示红点(聚合提醒)。
  • 二级导航 icon(Activity Award / Invitation bonus / Betting rebate / Super Jackpot / First gift / Invite Wheel):每个入口独立判断,有奖励待领 / 可参与 → 显红点;可领多项或可抽次数显数字角标(First gift「2」、Invite Wheel 显可抽次数「3」)。
  • 底部导航中间改为「存款 Deposit」入口(替代原邀请转盘位置):存款有奖励时用礼物图标 🎁 标识引导充值领奖;邀请转盘移入 Activity 二级 icon,达条件用红点 / 数字表示。
  • banner(Gifts / Attendance bonus)同样适用:如签到 Attendance bonus 今日可领 → 显红点。
  • 红点消除:对应奖励领完 / 不再满足条件后红点消失;底部 Activity 红点在其下所有入口红点都消失后消失。

数据支撑(代码事实)

  • 奖励中心 GetRewardCenterList 返回每项 ReceiveStatus(0不能领 / 1可领)→ 可领即红点。
  • 「可参与」用 ReceiveState=3 段 MaxRewardableAmount/Rate + 达标判定。
  • 底部 Activity 红点 = 各入口「可领 ∨ 可参与」逻辑或聚合;以纯前端为主,后端可补一个轻量红点聚合接口。
▸ 切换:全部领取后(红点消失)
